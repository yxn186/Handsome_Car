# YXN_ECF 使用指南

## 1. 当前工程中的使用方式

`YXN_ECF` 用来集中存放 Handsome_Car 使用的通用算法、BSP 和功能模块，
所需源码由工程根目录的 `CMakeLists.txt` 显式接入。

```text
Handsome_Car/
├── YXN_ECF/               通用算法、BSP 和功能模块
├── Usercode/              Handsome_Car 自己的 App 和 Task
├── Core/                  CubeMX 生成代码
├── CMakeLists.txt         YXN_ECF 的接入位置
└── Handsome_Car.ioc
```

## 2. YXN_ECF 与 Usercode 的职责

`YXN_ECF` 用来存放可以在不同 STM32 工程之间复用的代码，例如：

- `algorithm/`：PID、滤波、前馈和数学算法；
- `bsp/`：CAN、SPI、I2C、USART、DWT 等板级接口；
- `module/`：电机、传感器、显示和输入设备模块。

`Usercode` 用来存放 Handsome_Car 自己的代码，例如：

- `Handsome_Car_Task`；
- 本车专用 App；
- 与当前整车状态机、控制流程相关的代码。

接入位置也不同：

```text
YXN_ECF 源码    -> 顶层 CMakeLists.txt
Usercode 源码   -> Usercode/CMakeLists.txt
```

不要把 YXN_ECF 的公共模块再次写入 `Usercode/CMakeLists.txt`。

## 3. 在顶层 CMake 中定义目录

工程根目录的 `CMakeLists.txt` 使用：

```cmake
set(YXN_ECF_DIR
    "${CMAKE_CURRENT_SOURCE_DIR}/YXN_ECF"
)
```

这里的 `CMAKE_CURRENT_SOURCE_DIR` 就是 `Handsome_Car` 工程根目录，因此
`YXN_ECF_DIR` 最终指向：

```text
D:\AAA_HandsomeCar\Handsome_Car\YXN_ECF
```

YXN_ECF 中包含 C++ 源文件，所以顶层 CMake 还需要启用 C++：

```cmake
enable_language(C CXX ASM)

target_compile_features(${CMAKE_PROJECT_NAME} PRIVATE cxx_std_17)
```

## 4. 启用一个 YXN_ECF 模块

启用模块需要完成两件事：

1. 把 `.c/.cpp` 写入 `target_sources()`；
2. 把头文件所在目录写入 `target_include_directories()`。

例如，在 STM32F407 工程中启用 bxCAN、DJI Motor 和 PID：

```cmake
target_sources(${CMAKE_PROJECT_NAME} PRIVATE
    ${YXN_ECF_DIR}/bsp/CAN/bxCAN/bsp_can.c
    ${YXN_ECF_DIR}/bsp/CAN/bxCAN/bxcan_adapter.cpp
    ${YXN_ECF_DIR}/module/RM_Module/DJI_Motor/DJI_Motor.cpp
    ${YXN_ECF_DIR}/algorithm/PID/PID.cpp
)

target_include_directories(${CMAKE_PROJECT_NAME} PRIVATE
    ${YXN_ECF_DIR}/bsp/CAN
    ${YXN_ECF_DIR}/bsp/CAN/bxCAN
    ${YXN_ECF_DIR}/module/RM_Module/DJI_Motor
    ${YXN_ECF_DIR}/algorithm/PID
)
```

头文件不需要写入 `target_sources()`。只有 `.c/.cpp` 是编译单元。

## 5. 为什么不自动收集全部源码

工程不使用下面这种写法：

```cmake
file(GLOB_RECURSE YXN_ECF_SOURCES
    "${YXN_ECF_DIR}/*.c"
    "${YXN_ECF_DIR}/*.cpp"
)
```

原因是 YXN_ECF 同时包含不同 MCU 和不同外设的实现：

- STM32F407 使用 bxCAN；
- STM32H7 工程可能使用 FDCAN；
- SPI、I2C、USART、USB 等 BSP 需要 CubeMX 先生成对应外设；
- 某些模块还依赖 DMA、GPIO 引脚定义或其他 BSP。

如果递归编译整个目录，会把不属于当前芯片或尚未配置的模块一起加入，导致
缺少类型、头文件、HAL 函数或外设句柄等错误。

因此正确方式是：源码全部保存在 `YXN_ECF`，当前工程需要哪些，就在顶层
`CMakeLists.txt` 中明确启用哪些。

## 6. STM32F407 的 CAN 选择

Handsome_Car 当前芯片是 STM32F407，应使用：

```text
YXN_ECF/bsp/CAN/bxCAN/
```

对应 CMake：

```cmake
${YXN_ECF_DIR}/bsp/CAN/bxCAN/bsp_can.c
${YXN_ECF_DIR}/bsp/CAN/bxCAN/bxcan_adapter.cpp
```

不要在当前工程中启用：

```text
YXN_ECF/bsp/CAN/FDCAN/
```

FDCAN 实现用于具备 FDCAN 外设的 MCU，例如参考工程中的 STM32H7。直接放进
F407 的编译列表会出现 `FDCAN_HandleTypeDef` 等类型不存在的问题。

## 7. 启用依赖外设的模块

添加 SPI、I2C、USART、PWM、USB 等模块前，先检查 CubeMX 是否已经生成所需
内容。

例如启用 `bsp_spi.cpp` 前，应确认工程具备：

- 已配置的 SPI 外设；
- `spi.c/.h`；
- 对应的 STM32 HAL SPI 驱动源文件；
- 需要时配置 DMA；
- 业务模块所需的片选和中断引脚。

然后再在顶层 CMake 中同时加入源文件和头文件目录：

```cmake
target_sources(${CMAKE_PROJECT_NAME} PRIVATE
    ${YXN_ECF_DIR}/bsp/SPI/bsp_spi.cpp
)

target_include_directories(${CMAKE_PROJECT_NAME} PRIVATE
    ${YXN_ECF_DIR}/bsp/SPI
)
```

仅仅把源码复制到 `YXN_ECF` 文件夹，不代表它已经参加编译。

## 8. 添加新的公共模块

假设新增一个滤波模块：

```text
YXN_ECF/algorithm/NewFilter/NewFilter.cpp
YXN_ECF/algorithm/NewFilter/NewFilter.h
```

顶层 CMake 增加：

```cmake
target_sources(${CMAKE_PROJECT_NAME} PRIVATE
    ${YXN_ECF_DIR}/algorithm/NewFilter/NewFilter.cpp
)

target_include_directories(${CMAKE_PROJECT_NAME} PRIVATE
    ${YXN_ECF_DIR}/algorithm/NewFilter
)
```

代码中即可使用：

```cpp
#include "NewFilter.h"
```

## 9. 更新 YXN_ECF


推荐步骤：

1. 对比参考目录与当前 `YXN_ECF`；
2. 只复制需要更新的公共模块；
3. 检查顶层 CMake 中的源文件路径是否仍然正确；
4. 新增源文件时显式加入 `target_sources()`；
5. 新增头文件目录时显式加入 `target_include_directories()`；
6. 重新执行 CMake Configure 和 Build。


## 10. 不要修改生成的 CMake 文件

YXN_ECF 的接入写在工程根目录：

```text
Handsome_Car/CMakeLists.txt
```

不要写入：

```text
Handsome_Car/cmake/stm32cubemx/CMakeLists.txt
```

后者由 STM32CubeMX 生成，以后重新生成工程时可能被覆盖。

## 11. 常见问题

### 找不到头文件

检查对应目录是否已经加入 `target_include_directories()`，并确认模块需要的
CubeMX 外设头文件已经生成。

### 出现 undefined reference

通常表示只有头文件路径，没有把实现文件加入 `target_sources()`；也可能是
相应 HAL 驱动没有加入当前工程。

### 出现 FDCAN 类型不存在

当前是 STM32F407，应改用 `bsp/CAN/bxCAN`，不要启用 `bsp/CAN/FDCAN`。

### 文件已经复制但没有编译

这是显式 CMake 管理的正常行为。把新的 `.c/.cpp` 路径加入顶层
`target_sources()`，然后重新执行 CMake Configure。

## 12. 快速检查表

每次启用新模块前确认：

- [ ] MCU 与模块实现匹配；
- [ ] CubeMX 已生成所需外设；
- [ ] `.c/.cpp` 已加入顶层 `target_sources()`；
- [ ] 头文件目录已加入顶层 `target_include_directories()`；
- [ ] 没有修改 CubeMX 生成的 CMake 文件；
- [ ] CMake Configure 通过；
- [ ] 编译和链接通过；
- [ ] 上板前已检查引脚、总线和供电配置。
